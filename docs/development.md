# 開発・実行手順

## 環境構築・起動

- Python 3.11以上を使用する。検証環境はWindows、Python 3.14.5である。他のPythonバージョンとmacOS・Linuxでの動作は未検証である。
- 以下のコマンドは取得したリポジトリのルートで実行する。仮想環境の有効化は不要である。
- アプリ実行用は `requirements.txt`、テストを含む開発用は `requirements-dev.txt` を使用する。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m flask --app labtranslator init-db
.\.venv\Scripts\python.exe -m flask --app labtranslator run --host 127.0.0.1 --port 5000
```

- ブラウザーで http://127.0.0.1:5000 を開く。
- 起動時にもSQLiteのテーブルと初期13項目・別名を登録する。`init-db` は再実行可能であり、既存の用語編集を上書きしない。
- macOS・Linuxでは仮想環境のPythonを `.venv/bin/python` に読み替える。外部ツールとフォントも環境に応じて設定する。
- ローカル専用である。認証、インターネット公開運用、実際の患者情報の取り扱いは対象外である。

## 第1版の入力・比較・修正

- 通常アップロードはPDFのみである。ドラッグ＆ドロップとファイル選択に対応する。20 MB以内・1～20ページとし、暗号化PDFは受け付けない。リクエスト全体にも20 MiBの上限があるため、上限ぎりぎりのファイルは拒否される場合がある。
- デモA・B・Cは同梱の `demo_data/LabTranslator_Demo_A.pdf`、B、Cをそのまま読み込む。形式選択やExcelシート操作はない。抽出に失敗してもExcelの正解データには切り替えない。
- 文字情報を持つPDFはpdfplumberで文字と座標を抽出する。左に原本プレビュー、右に英訳報告書を表示する。
- Popplerで原本の各ページを画像化して表示する。原本PDF自体は変更しない。拡大・縮小、スクロール、原ファイル表示に対応する。
- 列見出しと座標から検査項目・検査値・単位・基準範囲を識別する。複雑な多段表や縦書きなど、任意の帳票の完全解析は保証しない。欠落情報や空欄の基準範囲は補完しない。
- 受付番号・報告日・検体・依頼元・検査施設は、原資料に存在するもののみ抽出する。既知の表現を英訳し、未知の日本語は要確認とする。日付や番号は補完しない。
- 原資料、未修正の抽出文字列、利用者の修正値を区別して保存する。項目名や上部情報を選択し、詳細画面で確認・修正する。検査値・単位・基準範囲は翻訳・単位変換・丸めを行わない。
- 検査項目は文字列正規化と用語マスターで照合する。英語略語を保持し、日本語部分を英訳する。未登録・曖昧な表現は推測翻訳しない。
- Excel・CSV・画像の読み込み処理は内部検証用に残すが、第1版の通常アップロードでは受け付けない。Excelは期待結果の検証にも使用する。数式計算は対象外である。

## 報告書単位の手動英訳

- 項目の詳細画面で「英訳（English）」を修正し、確認状態を指定して保存する。手動英訳は現在の報告書だけに反映し、用語マスターや別名を自動更新しない。
- 用語マスターで再照合しても手動英訳を保持する。標準訳語へ戻す操作で手動修正を取り消せる。
- 検査項目名・検査値・単位・基準範囲を変更すると手動英訳の確認状態を解除する。英訳そのものは保持し、比較画面に「英訳の再確認が必要」と表示する。
- 元の照合状態と利用者の英訳確認状態は別々に管理する。未登録・要確認でも、原資料との確認と手動英訳の確認を満たせば、その報告書の出力に使用する。
- 未確認の手動英訳はPDF・Excelで空欄になる。出力画面に件数・理由と該当項目へのリンクを表示する。原資料との確認や必須欄が不足する場合も出力には使用しない。
- OCR再抽出は行データを置き換えるため、手動英訳がある場合は破棄を明示的に選択する必要がある。

## Poppler・日本語OCR

- Popplerの `pdftoppm` は原本プレビューと画像化PDFのOCR前処理に使用する。文字PDFのテキスト抽出自体には不要である。
- OSに対応するPopplerを導入し、`pdftoppm` をPATHに追加するか、実行ファイルを指定する。以下は配置例である。

```powershell
$env:PDFTOPPM_CMD = 'C:\tools\poppler\Library\bin\pdftoppm.exe'
& $env:PDFTOPPM_CMD -v
```

- Popplerがない場合、画像化した原本プレビューは利用できない。原ファイルリンクやブラウザーのPDFビューアーを利用する。ビューアーの表示可否はブラウザー環境に依存する。
- OCRはTesseract 5系、`pytesseract`、Pillowを使用する。Tesseract本体と日本語 `jpn`・英語 `eng` の言語データはpipでは導入されない。
- 導入は [Tesseract公式導入資料](https://tesseract-ocr.github.io/tessdoc/Installation.html) と [公式言語データ資料](https://tesseract-ocr.github.io/tessdoc/Data-Files.html) を参照する。

```powershell
$env:TESSERACT_CMD = 'C:\Program Files\Tesseract-OCR\tesseract.exe'
& $env:TESSERACT_CMD --version
& $env:TESSERACT_CMD --list-langs
```

- `jpn` と `eng` の両方が表示されることを確認する。macOS・LinuxではPATH上のTesseractを使用するか、実際のパスを設定する。
- 文字情報がないPDFはPopplerで200 dpiのPNGに変換してOCRする。比較画面からPDFを強制的にOCRで再抽出することもできる。
- OCR接続・呼び出し・抽出結果の修正・失敗記録の処理は実装済みである。ページごとの抽出経路と状態、警告を記録する。
- Tesseract未導入の検証環境では実OCR精度は未検証である。接続処理のテスト成功を認識精度の検証完了と扱わない。
- 必要な外部ツールや言語データがない場合は警告を表示する。推測補完せず、抽出全文の確認、手動行追加・除外・修正を行う。OCR行は要確認とし、原資料との照合を利用者が行う。

## PDF・Excel出力とフォント

- 比較画面の「出力へ」から出力専用画面へ移動し、PDFまたはExcelを選択する。CSV出力処理は残すが、画面の選択肢には表示しない。
- PDFは右側プレビューと同じ報告書データから表形式で生成する。原資料のレイアウトを保持した英訳PDFや画像上の置換ではない。
- PDFには英訳項目名・検査値・単位・基準範囲・状態と上部情報を出力する。未確定項目がある場合は注意書きを表示する。
- Excelは原文・英訳・検査値・単位・照合状態・基準範囲等を文字列セルとして出力し、上部情報は別シートに出力する。修正した項目は修正後の値を使用し、原資料の値も別に保持する。
- ReportLabが読み込めるTrueTypeフォントが必要である。出力に含まれる英語・数値・単位・特殊記号、必要に応じ日本語・全角記号の字形を備えたフォントを用意する。
- 検索順は `PDF_FONT_PATH`、Windowsのメイリオ、Arial、LinuxのDejaVu Sansである。最初に存在するファイルを使用し、不足字形があればエラーにする。別フォントへの自動的な字形補完は行わない。
- Windows以外では既定フォントが存在しない、または必要な字形が不足する場合がある。適切なフォントを明示する。フォントはリポジトリに同梱しない。

```powershell
$env:PDF_FONT_PATH = 'C:\Windows\Fonts\meiryo.ttc'
```

## データ保存

- `instance/labtranslator.db` に用語マスター・別名・変更履歴を保存する。
- `instance/<UUID>/source.pdf` に原資料、`job.json` に抽出・修正・照合結果・確認状態を保存する。プレビュー画像も同じジョブフォルダーに保存する。
- DB、アップロード、job.json、仮想環境、キャッシュ、一時ファイル、環境変数ファイル、個人用LOCAL_NOTES.mdはGit対象外とする。
- 自動削除機能はない。サーバー停止後に不要なジョブフォルダーを削除する。DB削除では利用者の用語編集も失われる。
- 変更者は初期投入 `seed`、画面操作 `local-user` とする。本人識別と複数利用者の同時更新は対象外である。

## テスト

- Pythonテストはpytest、アップロード画面のJavaScriptテストはNode.jsの標準テストランナーを使用する。Node.js 24.19.0で検証している。npmパッケージの導入は不要である。

```powershell
.\.venv\Scripts\python.exe -m pytest -q -rs --basetemp=tmp/pytest
node --test tests/upload.test.cjs
.\.venv\Scripts\python.exe scripts/verify_demos.py
```

- pytestはExcelの「期待結果・検証」シートとデモA・B・Cの合計30件を比較する。PDF通常抽出各10件、値・単位・基準範囲、修正・手動英訳・再照合、PDF・Excel出力、主要な画面操作を検証する。
- JavaScriptテストはファイル選択・ドラッグ＆ドロップ・形式やサイズ等の拒否動作を検証する。実ブラウザーの視覚確認とは別である。
- OCR実測テストはTesseract・言語データ・必要なPopplerがない場合にスキップする。成功・失敗・スキップを区別して確認する。
- `verify_demos.py` はPDF通常抽出・PDF強制OCR・PNG OCRの名称翻訳一致数、値・単位を含む一致数、警告、不一致を表示する。依存未導入時の0件は精度測定結果ではない。
- pytestの一時ファイルは `tmp/pytest` に、キャッシュは `.pytest_cache/` 等に生成され、Git対象外になる。実OCR精度と他OSの再現性は別途検証する。

## 対象外

- 原資料のレイアウトを保持した英訳出力、画像内日本語の直接置換、OCR誤認識の自動補正。
- 外部翻訳API、生成AI翻訳、個人情報の検出・マスキング、実際の患者情報の取り扱い。
- 数式計算、任意帳票の完全自動解析、マスターの一括取込・削除・無効化、認証、本番公開運用。
