# LabTranslator 要件定義書

## 1. プロジェクト概要

### 1.1 アプリケーション名

**LabTranslator**

Pythonによる検査項目の表記揺れ統一・英訳支援Webアプリ

### 1.2 開発背景と課題

医療文書に記載される検査結果の翻訳には、次のような課題がある。

- **報告書の形式の違い**  
  医療機関や検査施設によって、報告書の形式や検査項目の配置、表記方法が異なる。

- **PDF・画像からの文字の読み取り**  
  検査結果はExcelやWordなどの編集可能なデータではなく、PDFやスクリーンショットなどの形式で提供されることも多く、検査項目の読み取りや転記に手間がかかる。画像から文字を読み取るOCRを利用する場合も、文字の誤認識が生じることがある。

- **検査項目名の表記揺れ**  
  同じ検査項目であっても、全角・半角、スペースの有無、漢字・カタカナ、略語など、さまざまな表記揺れが存在する。

- **用語検索の難しさ**  
  文字列の完全一致による検索では、わずかな表記の違いによって該当する用語を取得できない場合がある。

- **用語の登録・管理の負担**  
  表記パターンを個別に登録する方法では、用語数の増加に伴い、登録・検索・更新の負担が大きくなる。

### 1.3 開発目的

LabTranslatorは、Pythonによる文字列正規化とデータベースによる用語管理を組み合わせ、検査項目名の表記揺れに対応し、日本語から英語への翻訳を支援するWebアプリとして開発する。

検査値や単位などの原資料の情報を保持しながら、検査項目の英訳、未登録用語の確認、用語マスターの継続的な更新を可能にすることで、翻訳作業の負担軽減と正確性の向上を目指す。

第1版はPDFの通常アップロード、文字抽出、原本プレビュー、確認・修正、PDF・Excel出力を実装している。画像化PDFの日本語OCR連携は実装済みだが、実際の認識精度は未検証である。元のレイアウトを保持した英訳出力は未実装とする。

## 2. 基本方針

### 2.1 原資料の情報を保持する

- 入力された原資料は変更せずに保持する。
- 検査値・単位は、原資料に記載された文字列を原則として変更しない。
- 既存の英語略語は原則として保持する。
- 日本語部分を英訳する際も、原資料の情報を不必要に変更しない。
- 照合用の正規化文字列と、出力用の翻訳文字列を分けて管理する。
- 原文、照合結果、翻訳結果を比較できるようにする。

### 2.2 誤変換を防止する

- 文字列の一部が一致するだけで、同じ検査項目と判断しない。
- 異なる検査項目を誤って統一しない。
- OCRによる誤認識が疑われる場合は、自動的に確定せず、人による確認を必要とする。
- 未登録の用語や複数の候補が存在する用語は、確認対象として扱う。
- 用語マスターへの登録は、確認済みの内容を対象とする。

## 3. 入力データ

### 3.1 対応する入力形式

第1版の通常アップロードはPDF形式のみとする。

| 入力形式 | 現在の対応状況 |
|---|---|
| PDF（.pdf） | ファイル選択・ドラッグ＆ドロップに対応する |
| Excel（.xlsx）・CSV（.csv） | 内部の読み込み処理とテストを維持するが、通常アップロードでは受け付けない |
| 画像（.png / .jpg / .jpeg） | 内部のOCR接続処理を維持するが、通常アップロードでは受け付けない |

- PDFは20 MB以内・1～20ページとし、暗号化PDFは受け付けない。リクエスト全体にも20 MiBの上限がある。
- 文字情報を持つPDFはpdfplumberで抽出し、画像化PDFはPopplerとTesseractのOCR経路で処理する。実OCR精度は未検証である。

### 3.2 デモデータ

開発・検証には、公開可能な架空の検査結果を使用する。

- 異なる表記方法の既存デモA・B・CのPDFを使用する。形式選択やExcelシート操作は表示しない。
- PDF抽出に失敗してもExcelの期待値へ自動的に切り替えない。Excel・PNGは検証用に維持する。
- 基本の検査項目は10項目とする。
- 各デモで検査項目名の表記を変え、架空の検査値・単位は共通にする。
- 実際の患者情報や実務で使用した検査結果は使用しない。
- 表記揺れ、OCR誤認識、誤統一防止の検証データを用意する。

## 4. 検査項目の正規化・照合

### 4.1 文字列の正規化

Pythonを使用し、次のような表記の違いを正規化する。

- 全角・半角
- 英字の大文字・小文字
- スペースの有無
- 全角括弧・半角括弧
- 必要に応じた記号の違い

正規化は主に用語照合のために行い、原文を上書きしない。

### 4.2 別名の照合

漢字・カタカナ・ひらがな、旧称、略語など、文字列正規化だけでは対応できない名称の違いは、用語マスターに登録した別名を利用して照合する。

#### 総蛋白の例

| 入力 | 期待する英訳 |
|---|---|
| 総蛋白 | Total Protein |
| 総タンパク | Total Protein |
| 総たんぱく | Total Protein |
| ＴＰ（総タンパク） | TP(Total Protein) |

#### アルブミンの例

| 入力 | 期待する英訳 |
|---|---|
| アルブミン | Albumin |
| Alb(アルブミン) | Alb(Albumin) |
| Ａｌｂ（アルブミン） | Alb(Albumin) |
| Alb ( アルブミン ) | Alb(Albumin) |
| ALB（アルブミン） | ALB(Albumin) |

全角・半角や不要なスペースは出力時に統一する。ただし、英語略語の大文字・小文字は原則として保持する。

### 4.3 部分翻訳

日本語と英語が混在する検査項目名では、日本語部分のみを英訳する。

例：

- `Alb(アルブミン)` → `Alb(Albumin)`
- `TP(総蛋白)` → `TP(Total Protein)`
- `AST(GOT)` → `AST(GOT)`

意味を確認できない語句や修飾語が含まれる場合は、安易に削除・置換せず、確認対象とする。

## 5. OCRと誤認識への対応

### 5.1 文字抽出

以下の処理を実装している。

- 文字PDFから検査項目名・検査値・単位・基準範囲を抽出する。
- 画像化PDFはPopplerで画像化し、pytesseract経由でTesseractの日本語・英語OCRを呼び出す。画面から強制OCRで再抽出する経路もある。
- 左側に原本、右側に英訳報告書を表示する。原本画像プレビューにもPopplerを使用する。
- OCR抽出文字列と利用者の修正値を分け、OCR行は要確認として扱う。行追加・除外・修正・再照合に対応する。
- ページごとの抽出経路・処理状態・警告を記録する。列対応や欠落情報を推測補完しない。
- 受付番号・報告日・検体・依頼元・検査施設は、原資料に存在するもののみ抽出する。既知の表現を英訳し、未知の日本語は確認対象とする。上部情報の確認・修正に対応する。
- Tesseractや言語データがない場合は警告を表示する。実際のOCR認識精度は未検証であり、接続処理のテストと精度検証を区別する。
- 複雑な多段表や縦書きなど、任意帳票の完全な抽出は保証しない。導入・実行手順は `development.md` を参照する。

### 5.2 OCR誤認識の確認

OCR誤認識に対する修正候補の自動提示は未実装である。現在はOCR行を要確認とし、未登録語や複合表記の意味不一致を検出する。利用者が原資料を照合して修正する。

#### 総ビリルビンの例

| 入力・認識結果 | 処理方針 |
|---|---|
| 総ビリルビン | Total Bilirubin |
| Ｔ－Ｂｉｌ（総ビリルビン） | T-Bil(Total Bilirubin) |
| 総ビリルピン | 未登録として扱い、利用者が原資料と照合する |
| 総ビリルビソ | 未登録として扱い、利用者が原資料と照合する |

OCRの誤認識が疑われる文字列を、確認なしに正式な別名として登録しない。

### 5.3 誤統一の防止

次の検査項目は、それぞれ独立した項目として管理する。

| 日本語名 | 英語名 |
|---|---|
| 総ビリルビン | Total Bilirubin |
| 直接ビリルビン | Direct Bilirubin |
| 間接ビリルビン | Indirect Bilirubin |

「ビリルビン」という文字列が共通していても、同一の検査項目として扱わない。

## 6. 用語マスター管理

### 6.1 検査項目マスター

検査項目ごとの標準日本語名と標準英語名を管理する。

- 検査項目ID
- 標準日本語名
- 標準英語名
- 検体の種類（必要に応じて設定）
- 登録日時
- 更新日時

### 6.2 別名マスター

1つの検査項目に対して、複数の別名・略語を登録できるようにする。

- 別名ID
- 検査項目ID
- 別名・略語
- 正規化後の照合用文字列
- 別名固有の英訳と検体情報
- 登録日時

全角・半角やスペースの違いだけで生じる表記パターンは、原則として個別登録しない。

### 6.3 用語の追加・更新

- 新しい検査項目を登録できるようにする。
- 既存の検査項目に別名を追加できるようにする。
- 登録済みの用語を編集できるようにする。
- 既存の用語との重複や正規化後の衝突を確認する。
- 未登録用語は確認後にマスターへ登録する。

### 6.4 変更履歴

用語マスターの変更を追跡できるようにする。

- 変更対象
- 登録・更新の操作（削除機能は未実装）
- 変更前の内容
- 変更後の内容
- 変更者
- 変更日時

登録・更新と履歴は同一トランザクションで保存する。変更者は初期投入時 `seed`、画面操作時 `local-user` とする。利用者認証による本人識別は未実装である。

## 7. 翻訳結果の出力

### 7.1 PDF・Excel形式（実装済み）

- 出力専用画面でPDFまたはExcelを選択する。CSVの出力処理・URLは残すが、画面の選択肢には表示しない。
- PDFは右側プレビューと同じ報告書データから表形式の英訳報告書を生成する。英訳項目名・検査値・単位・基準範囲・状態と上部情報を出力する。
- Excelは原文・修正後の名称・英訳・検査値・単位・照合状態・基準範囲等を文字列セルで出力し、上部情報は別シートに出力する。
- 検査値・単位・基準範囲は翻訳・丸め・単位変換を行わない。利用者が修正した場合は修正後の値を出力し、抽出時の値も保持する。空欄は補完しない。
- 除外行は出力しない。未確定の英訳は空欄とし、画面とPDFに注意を表示する。
- PDF出力には必要な字形を持つTrueTypeフォントが必要である。設定は `development.md` を参照する。

### 7.1.1 報告書単位の手動英訳（実装済み）

- 詳細画面の英訳入力欄は用語マスターの候補、または保存済みの手動英訳を表示する。
- 手動英訳は対象報告書だけに保存し、用語マスターを自動更新しない。通常の再照合でも保持し、標準訳語へ戻す操作で取り消せる。
- 検査項目名・検査値・単位・基準範囲の変更時は、手動英訳を保持して確認状態を解除する。比較画面に英訳の再確認が必要と表示する。
- 元の照合状態と利用者の確認状態は分ける。原資料との確認・必須欄・手動英訳の確認を満たす場合は、未登録・要確認項目でも手動英訳を出力できる。
- 未確認の手動英訳は空欄で出力する。出力画面に件数・理由・該当行へのリンクを表示する。

### 7.2 レイアウトを維持したPDF・画像形式（未実装）

将来は、元の報告書のレイアウトを可能な範囲で維持した翻訳結果の生成を検討する。現在の表形式PDF出力とは区別する。

- 原資料の画像やPDFを変更せずに保持する。
- 日本語部分の英訳を元の位置に反映する。
- 検査値・単位・英語略語を不必要に変更しない。
- 英訳後の文字数による配置の変化など、レイアウト上の制約を考慮する。
- 自動処理で正確に再現できない場合は、確認・修正を必要とする。

### 8.2 テーブル構成

- `lab_terms`：検査項目マスター

### 9.2 主な画面（実装済み）

## 10. 検証・テスト

### 10.1 正規化・照合のテスト

- 全角・半角の違いを吸収できること。
- スペースや括弧の違いを吸収できること。
- 別名から正しい検査項目を照合できること。
- 異なる検査項目を誤って統一しないこと。
- 英語略語を原則として保持できること。
- 日本語と英語が混在する名称を部分翻訳できること。

### 10.2 データ保持のテスト

- 検査値が変更されないこと。
- 単位が変更されないこと。
- 原文が保持されること。
- 未確認の用語が勝手に確定されないこと。

### 10.3 用語マスターのテスト

- 検査項目を登録できること。
- 既存項目に別名を追加できること。
- 重複・衝突を検出できること。
- 変更履歴を記録できること。

### 10.4 テスト技術

Pythonの `pytest` とNode.jsの標準テストランナーを使用する。OCR実測テストは外部依存がない場合にスキップし、実施済みと扱わない。テスト手順は `development.md` を参照する。

## 11. 実装状況

### 実装済み

- 架空デモPDF、文字列正規化、用語マスター照合、部分翻訳。
- SQLite・SQLAlchemyによるマスター・別名・登録更新履歴の管理。
- FlaskによるPDF読み込み、原本プレビュー、左右比較、行・上部情報の修正、再照合。
- 報告書単位の手動英訳・確認状態管理、PDF・Excel出力。
- 自動テストとOCR接続・失敗記録の処理。

- macOS・Linux等、検証環境以外での動作。

### 未実装・今後の検討

- OCR誤認識の修正候補の自動提示。

- 原本と同じ位置へ英語を配置する出力。

## 12. 医療情報・守秘義務

- 開発・検証には公開可能な架空のデータを使用する。
- 実際の患者情報や実務で使用した検査結果は使用しない。
- 特定の医療機関や勤務先の非公開情報を使用しない。
- 用語マスターは公開可能な一般的な検査項目名を使用して作成する。
- 翻訳結果は人による確認を前提とし、医療上の判断を自動化するものではない。
